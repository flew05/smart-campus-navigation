СОВЕТЫ ПО ЭКОНОМИИ МЕСТА
─────────────────────────

Если какие-то разделы получаются слишком длинными:

1. CLASS DEFINITIONS (если > 2 страниц):
   - Оставь полные описания для 6-8 самых важных классов:
     * User, Location, Route, NavigationService
     * Schedule, Notification, Building
   - Для остальных сократи описания до 2-3 строк

2. USE CASE DESCRIPTIONS (если > 2 страниц):
   - Сократи Extensions до 2-3 самых важных
   - Убери некоторые детали из Main Flow

3. FFBD EXPLANATORY NOTE (если > 2 страниц):
   - Сократи описания отдельных функций
   - Оставь главное: логику декомпозиции и rationale
