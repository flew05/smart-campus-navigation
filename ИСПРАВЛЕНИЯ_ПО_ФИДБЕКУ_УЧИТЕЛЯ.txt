5. АВТОМАТИЧЕСКАЯ НАВИГАЦИЯ ПО РАСПИСАНИЮ
──────────────────────────────────────────

Добавить FR13 (уже включен в таблицу выше):

FR13: The system shall automatically suggest navigation to the next class 15 
minutes before scheduled start time based on user's integrated schedule.

Justification: Proactive navigation alerts prevent students from forgetting 
about classes or leaving too late. The 15-minute window accounts for average 
walking time across campus. This directly addresses Problem 1 (tardiness) and 
Problem 2 (missed classes due to schedule changes).

Implementation: When a class is scheduled to start within 15 minutes and user 
is not already near the location, the system sends a notification: "Your next 
class (Course Name) starts in 15 minutes at Building Room. Navigate now?" 
Tapping the notification launches turn-by-turn navigation automatically.


6. БЕЗОПАСНОСТЬ - GUEST MODE ОГРАНИЧЕНИЯ
─────────────────────────────────────────

Обновить NFR5 (уже включено в таблицу выше):

NFR5: Security - Data Privacy and Access Control

The system shall encrypt all user location data and schedule information using 
TLS 1.3 during transmission and AES-256 at rest.

Access Control by User Type:
- Authenticated Users (Students/Faculty): Full access to personalized features 
  (schedule integration, room booking, notification preferences, navigation history)
- Guest Mode: Read-only access to public information only (campus map, building 
  locations, facility search, basic navigation). Cannot access: room availability 
  details, schedule integration, booking systems, or user-specific data.

Justification: Location and schedule data are sensitive personal information. 
University must comply with FERPA (Family Educational Rights and Privacy Act) 
and protect student privacy. Guest mode limitations prevent unauthorized access 
to academic information while still serving prospective students and visitors.


7. SEQUENCE DIAGRAM - ACKNOWLEDGE MECHANISM
───────────────────────────────────────────

Обновить Explanation для Sequence Diagram 3 (раздел 6.3):

Добавить после "After reviewing, the Student sends "acknowledge"...":

The "acknowledge" action represents explicit user interaction with the 
notification. Implementation options include:
a) User taps a "Got it" or "OK" button within the notification detail screen
b) Dismissing the notification after viewing details
c) Taking action (e.g., starting navigation to new room)

The Mobile App logs this acknowledgment with timestamp and sends confirmation 
to the backend. This serves multiple purposes: confirms message delivery for 
critical notifications (room changes, emergencies), provides analytics on 
notification effectiveness, and allows instructors/administration to track 
which students have been informed of important changes. For non-critical 
notifications, implicit acknowledgment (viewing the notification) may be 
sufficient.

LOCATION (Улучшенная версия)
Purpose: Represents any physical place on campus requiring navigation or reference. 
This includes classrooms, offices, building entrances, landmarks, parking lots, and 
points of interest. Location serves as the fundamental geographic entity linking 
the map system with schedule management and navigation services.

Attributes: locationID, name, floor, coordinates

Relationships: Used-by Schedule (1:*), Referenced-by NavigationService, Displayed-on CampusMap
